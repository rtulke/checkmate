# DISA STIG

Automated checks for the Security Technical Implementation Guides (STIG) of
the US Defense Information Systems Agency, generated by `tools/cis-import`
from the goss audit content of
[Ansible Lockdown](https://github.com/ansible-lockdown) (MIT license, see
[NOTICE](NOTICE)). Do not edit the policies by hand; change the converter and
run `make stig-import`.

| Policy | STIG |
|---|---|
| `rhel7.yml` – `rhel10.yml` | Red Hat Enterprise Linux 7–10 and rebuilds |
| `ubuntu22.yml`, `ubuntu24.yml` | Ubuntu 22.04 and 24.04 LTS |
| `amazon2023.yml` | Amazon Linux 2023 |

Each policy only runs on its own platform (`defaults.when`). STIGs implement
NIST SP 800-53 controls: every check names its STIG ID, vulnerability ID,
rule ID, CCI and NIST control in the description, and the check name is the
STIG rule title.

Every check carries the rationale (vulnerability discussion) and the fix
text of its STIG rule, taken unchanged from the DISA XCCDF benchmark; they
are shown with `-vv` and in the HTML, PDF, CSV and XCCDF reports. Several
checks of one rule share its texts. The DISA releases are listed in
`STIG_DISA` in the Makefile:

| Policy | Checks from | Texts from DISA |
|---|---|---|
| `rhel7.yml` | V3R14 | V3R15, the final release: it only changes RHEL-07-020250, which is not part of the policy, and renumbers the rule revisions |
| `rhel8.yml` | V2R9 | V2R9 |
| `rhel9.yml` | V2R10 | V2R10 |
| `rhel10.yml` | V1R3 | V1R3 |
| `ubuntu22.yml` | V2R10 | V2R10 |
| `ubuntu24.yml` | V1R7 | V1R7 |
| `amazon2023.yml` | V1R5 | V1R5 |

Where the upstream audit names a wrong vulnerability ID for a STIG ID (eleven
rules of RHEL 7), the converter takes the IDs from the DISA benchmark.

## Selecting categories

| Tag | Selects | Severity |
|---|---|---|
| `stig` | every STIG check | |
| `stig-rhel9`, `stig-ubuntu24`, … | one STIG | |
| `stig-cat-1` | CAT I findings | high |
| `stig-cat-2` | CAT II findings | medium |
| `stig-cat-3` | CAT III findings | low |

```bash
sudo checkmate run stig/rhel9.yml --tags stig-cat-1
sudo checkmate run stig/ubuntu24.yml --fail-on high -v
sudo checkmate run stig/rhel9.yml --id 'STIG-RHEL-09-2*'
```

Rules that depend on optional features (graphical desktop, SSSD, routing,
FTP/TFTP servers) follow the defaults of the upstream audit and are left out.
The conversion and its deliberate deviations are described in
[cis/README.md](../cis/README.md); fixes for broken upstream commands (wrong
quoting that let awk errors pass, a NOPASSWD rule running an unrelated
command, home directory modes compared as decimal numbers) apply here too.

## Accepted deviations

Do not edit the generated policies to silence a finding. Keep accepted
deviations in a waiver file with a reason and an expiry date and pass it with
`--waivers` (see the [waivers reference](https://rtulke.github.io/checkmate/reference/waivers/)):

```yaml
waivers:
  - id: CIS-RHEL9-1.1.2.1.*
    reason: /tmp is a tmpfs mount managed by systemd
    until: 2027-06-30
```
